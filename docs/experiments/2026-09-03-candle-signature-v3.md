## ง. นิยามที่ตรึง (ต่อจาก V2 — ของเดิมไม่แก้)

### ง.1 Signature — **4 ตัวเดิม ไม่เพิ่ม ไม่ลด ไม่จูน** (ตามขั้นที่ 5)

`range/median20 > 1.5` · `|body|/range > 0.6` · `close_loc > 0.8` (up) หรือ `< 0.2` (down) ·
`volume/median20 > 1.2`

### ง.2 Regime (2 ชั้น) — คำนวณจาก 50 แท่งก่อนหน้า ไม่รวมแท่งตัวเอง

| ป้าย | เงื่อนไข |
|---|---|
| `directional` | `close > hi50` หรือ `close < lo50` หรือ `high > hi50` หรือ `low < lo50` หรือ `abs(close − close₋₅₀)/(hi50−lo50) > 0.5` |
| `range` | นอกเหนือจากนั้น |

**ต้องบันทึก regime 6 ชั้นย่อยไว้ในผลด้วย** (trend/breakout_up/breakout_down/sweep_high/sweep_low/range)
เพื่อให้ V4 ใช้ได้ทันทีโดยไม่ต้องรันซ้ำ — **แต่ห้ามทดสอบนัยสำคัญบนชั้นย่อย** ใน V3.

### ง.3 Matched baseline — **บังคับ ไม่ใช่ทางเลือก** (ตามขั้นที่ 3)

คู่เทียบต้องตรงกันทั้ง 4 อย่าง: `instrument` · `session (UTC date)` · `volatility tercile`
(แบ่งจาก `range/median20` ภายใน instrument) · `regime2`
และคู่เทียบคือ **แท่ง expanded ที่ไม่ strong** (`range/median20 > 1.5` แต่ตก body หรือ volume)

เหตุผลตรึงจาก V2: 1R = range ของแท่งสัญญาณ และเงื่อนไขคัดแท่ง range ใหญ่
⇒ baseline ที่ไม่ match ตัวหารจะต่างกัน ~2 เท่า และเคยเกือบทำให้ V2 สรุปผิด.

### ง.4 จุดตั้งต้นและ TP/SL — ของ V2 ทั้งหมด ไม่แก้

`entry = open ของแท่งถัดไป` · `1R = range แท่งสัญญาณ` · `SL = −1.0R` · `TP = +2.0R` ·
บาร์ที่กินทั้งสอง **นับเป็น stop** (`backtest.ts:204-209`) · รายงาน `ambiguous_rate` ·
บังคับ **แท่งติดกัน 5 นาทีเป๊ะ** ตลอด horizon (บทเรียนจาก V2 ที่ filter หลวมทำให้ผลปนเปื้อน)

### ง.5 สิ่งที่วัด (ตามขั้นที่ 2)

ที่ horizon **1, 3, 5, 10** ทุกค่าเป็นหน่วย R:

1. `MFE` · 2. `MAE` · 3. `return` (mark-to-close) · 4. `tp_before_sl` · 5. `sl_before_tp` ·
6. **`mae_before_mfe`** — ราคาแตะจุดแย่สุดก่อนหรือหลังจุดดีสุด (ของใหม่ที่ขั้นที่ 2 ขอ ตอบเรื่อง *เส้นทาง* ไม่ใช่ปลายทาง) ·
7. `ambiguous_rate`

**และเพราะคำถามคือเรื่อง distribution ไม่ใช่ค่าเฉลี่ย ต้องรายงาน quantile ด้วย:**
`p10 / p25 / p50 / p75 / p90` ของ MFE และ MAE ทั้ง cond และ matched —
ค่าเฉลี่ยอย่างเดียวตอบคำถามที่เจ้าของตั้งไม่ได้.

## จ. งบการทดสอบ — **16 ตัว ปิดรายการ**

> 2 ทิศ × 2 regime × 4 horizon = **16**

เกณฑ์นัยสำคัญ **p < 0.05/16 ≈ 0.0031** (Bonferroni) + bootstrap CI.
**ห้ามเพิ่มการทดสอบหลังเริ่มรัน.**

**สิ่งที่ *ไม่* นับเป็นการทดสอบ (เป็น descriptive ต้องรายงานแต่ห้ามอ้างนัยสำคัญ):**
- quantile ของ distribution
- sign test รายละเอียด instrument
- regime 6 ชั้นย่อย
- **directional asymmetry** (long บวก / short `H2_extreme` ไม่มี effect) — ตามที่เจ้าของสั่งไว้เอง
  ว่าให้เก็บเป็น **observation** ไม่ใช่ข้อสรุป จนกว่าจะแยก sampling noise ออกได้ที่ n พอ

## ฉ. เกณฑ์ตัดสิน V3 — **ต่างจาก V2 โดยตั้งใจ**

V2 ถามว่า "มี edge ไหม" และตอบว่าไม่รู้เพราะ n น้อย. V3 **ไม่ถาม** คำถามนั้นซ้ำ เพราะ n
ยังน้อยเท่าเดิม (ข้อ ข). V3 ถามสามข้อที่ n เท่านี้ตอบได้:

| # | คำถาม | ผ่านเมื่อ |
|---|---|---|
| A | pipeline ถูกไหม | matching ได้ ≥95% · `ambiguous_rate` ≤30% · ไม่มี horizon ไหน n ต่ำกว่า 50 |

**ห้ามประกาศ edge จาก V3 ไม่ว่าผลออกมาอย่างไร.** คำตัดสินเรื่อง edge อยู่ที่ V4.

1. matching ต่ำกว่า 95% ⇒ นิยาม matched baseline ใช้ไม่ได้ ต้องแก้ก่อน
2. `ambiguous_rate > 30%` ⇒ TP/SL ที่ 1R/2R ละเอียดเกินกว่า 5m bar จะตัดสิน
3. ทิศของ effect สลับไปมาระหว่าง horizon ในช่องเดียวกัน ⇒ สิ่งที่วัดอยู่คือ noise ไม่ใช่ signature

⇒ signature ตัวนี้**ไม่ได้ทำให้ราคาวิ่งไปไกลขึ้น มันทำให้ราคาย้อนน้อยลง** — และผลดีต่อ R

**descriptive เท่านั้น** ไม่ได้ทดสอบนัยสำคัญ.

## ญ.6 สิ่งที่ V3 **ไม่ได้** พิสูจน์

- ไม่มี edge ที่พิสูจน์แล้ว — 0/16 ผ่าน Bonferroni
- ไม่ได้พิสูจน์ว่าไม่มี edge — กำลังไม่พอตามที่ประกาศไว้ล่วงหน้า (ข้อ ข)
- ไม่ได้พิสูจน์ว่า `range` regime ดีกว่า `directional` อย่างมีนัยสำคัญ — **ยังไม่ได้ทดสอบผลต่างระหว่าง
  regime โดยตรง** (ไม่อยู่ใน 16 ตัวที่ตรึงไว้) ⇒ เป็น**ข้อสังเกต** ที่ต้องตรึงเป็นสมมติฐานของ V4
- ไม่มีข้อสรุปเรื่อง sweep/breakout (n = 2–41)
- ไม่มีข้อสรุปเรื่อง order flow (ไม่อยู่ใน V3)
- **OOS ตั้งแต่ 2026-09-04 ยังไม่ถูกแตะ**

## ญ.7 สิ่งที่ V4 ต้องทำ (ตรึงตอนนี้ ก่อนเห็นข้อมูลใหม่)

1. **สมมติฐานหลักของ V4 เปลี่ยนเป็น:** *"delta ของ `range` regime มากกว่า `directional` regime"* —
   ทดสอบผลต่างระหว่าง regime **โดยตรง** (interaction) ไม่ใช่ทดสอบแต่ละ regime แยกแล้วเทียบด้วยตา
2. **estimand หลักเป็น MAE p90 ไม่ใช่ mean R** — ญ.4 ชี้ว่า effect อยู่ที่หาง การวัดที่ mean
   ทิ้งกำลังทางสถิติไปเปล่า ๆ. ใช้ quantile regression หรือ bootstrap ของ p90
3. **เลิกใช้ `range_pos_50`** — V2 พิสูจน์แล้วว่ามันไม่แยก (เกณฑ์ข้อ 6). `regime2` แทนที่แล้ว
4. เงื่อนไขเริ่ม V4 เดิม: **≥21 session** (~2026-09-17) · n≥285/ช่อง
5. `breakout_down × short = −0.346` (n=41) เป็นข้อสังเกตที่แรงที่สุดฝั่งลบ — ตรึงเป็นสมมติฐานแยกของ V5
   เมื่อแก้นิยาม regime ให้เป็นอิสระจาก direction แล้ว

## ญ.8 เกณฑ์ตัดสิน V4 — รับมาจาก Signal-Only Forward Test Protocol ของเจ้าของ (ตรึงก่อน V4 รัน)

เจ้าของเสนอ protocol "H4 — Signal-Only Forward Test" เมื่อ 2026-09-03 พร้อมเกณฑ์ตัดสิน 4 ระดับ
หลังครบ 21 session. **V4 ยังไม่รัน ⇒ เกณฑ์นี้ยังนับเป็น pre-registration ได้** และแทนที่เกณฑ์
pass/fail แบบ Bonferroni เดี่ยวของ ญ.7 ข้อ 1–2 ด้วยระดับที่ละเอียดกว่า:

| ระดับ | เงื่อนไข |
|---|---|
| **FAIL** | interaction ระหว่าง regime ไม่มีนัยสำคัญ **และ** ไม่มี distributional difference ที่ MAE p90 |
| **INCONCLUSIVE** | มี effect ในทิศทางเดียวกับ V3 (`range` ดีกว่า `directional`) แต่ยังไม่ผ่าน p<0.0031 ที่ n≥285/ช่อง |
| **PROMISING** | effect สม่ำเสมอและทิศทางเดียวกันข้าม **instrument และ session** (ไม่ใช่แค่ pooled) — เกณฑ์นี้คือจุดที่ **เริ่มพิจารณาสร้าง Signal Observation Engine** (ดู ญ.9) |
| **VALIDATED** | ผ่าน PROMISING **และ** ผ่าน out-of-sample/walk-forward เพิ่มเติมหลังจากนั้น — เกณฑ์นี้เท่านั้นที่พิจารณา execution model ได้ |

**ห้ามเลือกระดับจากความรู้สึก** — ทั้ง 4 ระดับต้องอ้างอิงตัวเลขจริงจากผลรันตามหัวข้อ ก. ของ
protocol เจ้าของ (จำนวน opportunity, signal rate, MFE/MAE distribution ทุก percentile ที่ระบุ,
TP-before-SL, expectancy, แยกตาม instrument/regime/ทิศ) — ตัวเลขเหล่านี้ V3 มีให้แล้วเกือบครบ
(ดู ญ.2–ญ.5) เหลือเพียงคำนวณซ้ำที่ n ใหม่.

**"บันทึกทุก opportunity ไม่ใช่แค่ signal ที่ผ่าน"** ตามข้อ 6 ของ protocol เจ้าของ — **ทำอยู่แล้ว**
ผ่าน matched-baseline pool (แท่ง `expanded` ที่ตก body/volume คือ "opportunity ที่ไม่เข้า" กลุ่มนี้
ถูกใช้เป็นตัวหารการเทียบอยู่แล้วตั้งแต่ V2 ไม่ใช่ของใหม่ที่ต้องสร้าง).
